# Performance Monitor 仕様書

## 1. 概要

Windows のタスクマネージャー「パフォーマンス」タブ相当の情報を、**タブ切り替えなしで 1 画面に全部並べて**グラフ表示する常駐型モニターアプリ。
サブモニターや画面の隅に置いたまま、CPU・メモリ・ディスク・ネットワーク・GPU の状態をひと目で確認できるようにする。

### 1.1 目的

- タスクマネージャーでタブを切り替える手間をなくす
- 常に最前面に表示し、作業中でも負荷状況を確認できるようにする
- 監視アプリ自体の負荷は十分小さく抑える

### 1.2 対象外（本バージョンではやらないこと）

- プロセス単位の情報表示（プロセス一覧・プロセス別使用率）
- ログのファイル保存・長期履歴
- リモートマシンの監視
- Windows 以外の OS への対応

## 2. 動作環境

| 項目 | 内容 |
|---|---|
| OS | Windows 10 (1709 以降) / Windows 11, x64 |
| GPU 情報 | WDDM 2.x 以降のドライバ（タスクマネージャーで GPU が表示される環境なら可） |
| 権限 | 一般ユーザー権限で動作（管理者権限不要） |
| 配布形態 | 単一の `.exe`（インストーラーなし） |

## 3. 表示項目

タスクマネージャーと同じ値になることを基本方針とする。デバイスが複数ある項目（ディスク・ネットワーク・GPU）は**検出されたもの全てをそれぞれ別のタイルで表示**する。

### 3.1 CPU

| 項目 | 内容 |
|---|---|
| グラフ | CPU 使用率（全体）の時系列 0〜100% |
| 数値 | 使用率 %、現在のクロック (GHz) |
| スレッド別 | 全体グラフの下に、論理プロセッサ（スレッド）ごとの小グラフを縦 1 列に並べる。各グラフに番号と現在の使用率を表示（設定で ON/OFF、既定 ON） |
| 温度 | 表示しない（Windows 標準の手段では取得できない環境が多く、実温度の取得にはカーネルドライバと管理者権限が必要なため見送り） |

### 3.2 メモリ

| 項目 | 内容 |
|---|---|
| グラフ | 使用中メモリの時系列（0〜搭載容量） |
| 数値 | 使用中 / 搭載量 (GB)、使用率 %、コミット済み / コミット上限 (GB) |

### 3.2.1 ページング（メモリ列のメモリタイルの下）

| 項目 | 内容 |
|---|---|
| グラフ | ページファイル使用率 %（0〜100%）の時系列 |
| サブグラフ | ページイン（ディスクからの読み込み）・ページアウト（ディスクへの書き出し）の速度の時系列（2 系列重ね描き、縦軸は自動スケール） |
| 数値 | ページファイル使用率 %、ページイン / ページアウト (KB/s, MB/s)、ページファイル使用量 / サイズ (GB)。ページファイルが無い場合は「ページファイルなし」 |

### 3.3 ディスク（物理ディスクごと）

| 項目 | 内容 |
|---|---|
| タイトル | `ディスク 0 (C: D:)` のように番号と含まれるドライブレター |
| グラフ | アクティブな時間 %（0〜100%）の時系列 |
| サブグラフ | 読み取り速度・書き込み速度の時系列（2 系列重ね描き、縦軸は自動スケール） |
| 数値 | アクティブ時間 %、読み取り (MB/s)、書き込み (MB/s) |

### 3.4 ネットワーク（アダプタごと）

| 項目 | 内容 |
|---|---|
| 対象 | 状態が「接続済み」の全アダプタ（物理・仮想とも。Hyper-V, VMware, VPN 等の仮想アダプタも表示する）。ループバック、トンネル疑似インターフェース（Teredo 等）、フィルタードライバ、OS 内部用の隠しアダプタ（WAN Miniport 等）は除外 |
| タイトル | アダプタ名（例: `イーサネット`, `Wi-Fi`） |
| グラフ | 送信・受信のスループット時系列（2 系列重ね描き、縦軸は自動スケール） |
| 数値 | 送信 / 受信 (Kbps / Mbps / Gbps で自動単位切替)、アダプタの説明、リンク速度 |

### 3.5 GPU（GPU ごと）

| 項目 | 内容 |
|---|---|
| タイトル | `GPU 0 (NVIDIA GeForce RTX ...)` のように番号とアダプタ名 |
| グラフ | エンジン種別ごとの使用率時系列: 3D / Copy / Enc（Video Encode）/ Dec（Video Decode）/ Codec（AMD の Video Codec）。存在するエンジンのみ |
| 温度メーター | GPU 温度を横棒メーターで表示（0〜100℃）。警告しきい値（既定 80℃）以上で黄、危険しきい値（既定 90℃）以上で赤になり、危険時はタイルの枠も赤く強調する。ドライバが報告しない場合は「取得不可」 |
| ファンメーター | ファン回転数 (RPM) を横棒メーターで表示。上限はドライバが報告する最大回転数（不明なら 3000 RPM）。0 RPM は停止中（低温時にファンを止める準ファンレス動作など）。ドライバが報告しない場合は「取得不可」 |
| 数値 | 全体使用率 %（各エンジンの最大値。タスクマネージャー準拠）、専用 GPU メモリ 使用 / 総量、共有 GPU メモリ 使用 / 総量 |
| 備考 | 統合 GPU（Intel/AMD iGPU）も対象。Microsoft Basic Render Driver は除外 |

## 4. 画面仕様

### 4.1 レイアウト

- 1 ウィンドウ内に全項目を **タイル（カード）形式** で並べる
- 種類ごとに列を分け、左から **CPU → メモリ → GPU → ディスク → ネットワーク** の 5 列とする。各列の中でデバイスごとのタイルを縦に積む
- 列幅はウィンドウ幅を等分する（最小 190px。これより狭い場合は横スクロール）
- 縦に収まりきらない場合はスクロール。全項目を非表示にした列は詰める
- 既定のウィンドウサイズは 1100×640

```
┌────────┬────────┬────────┬────────┬────────┐
│ CPU    │ メモリ │ GPU 0  │ディスク0│イーサ  │
│ ▁▂▃▅▃ │ ▅▅▅▆▅ │ ▁▂▁▃▂ │ ▁▁▃▁▁ │ ネット │
│ 0 ▁▂▁ │        │ 温度 ■■│ ▁▂▁▁▁ │ ▁▃▁▂▁ │
│ 1 ▁▁▂ │        ├────────┼────────┼────────┤
│ 2 ▂▁▁ │        │ GPU 1  │ディスク1│ VMnet1 │
│ ...    │        │ ...    │ ...    │ ...    │
└────────┴────────┴────────┴────────┴────────┘
```

### 4.2 タイル

- 上部: タイトル + 主要な現在値（大きめのフォント）
- 中央: 時系列グラフ（直近 60 秒、右端が最新）
- 下部: 補助数値（小さめのフォント）
- 配色はダークテーマ固定（背景は暗色、文字・グラフは明色）
- 項目種別ごとにテーマ色を固定（タスクマネージャーに近い配色: CPU=青, メモリ=紫, ディスク=緑, ネットワーク=橙/茶, GPU=水色系）
- 2 系列グラフは実線（塗りつぶし）と破線で区別し、凡例を表示
- 凡例が 1 行に収まらない場合は折り返す
- ディスクとページングのタイルは、1 画面に収めるためグラフを CPU のスレッド別グラフと同じ高さ（細め）で描く

### 4.3 ウィンドウ挙動

| 機能 | 内容 | 既定値 |
|---|---|---|
| 常に最前面 | ON/OFF 切替可能 | ON |
| 枠なし表示 | タイトルバーを消してコンパクトにする。枠なし時はウィンドウ内のドラッグで移動、ウィンドウ端のドラッグでサイズ変更 | OFF |
| 不透明度 | 30〜100% で調整 | 100% |
| 位置・サイズ記憶 | 終了時に保存し、次回起動時に復元 | ― |
| 表示項目の ON/OFF | 個別のディスク・アダプタ・GPU 単位で非表示にできる | 全表示 |
| コンパクトモード | グラフ高さを縮め、補助数値と 2 つ目以降の折れ線グラフを省略（スレッド別グラフと温度メーターは残す） | OFF |
| 自動起動 | Windows へのサインイン時に自動起動する。`HKCU\Software\Microsoft\Windows\CurrentVersion\Run` に実行ファイルのパスを登録（管理者権限不要）。状態はレジストリを正とし、タスクマネージャーの「スタートアップ アプリ」で無効にした場合も OFF と表示する。メニューから ON にするとその無効化も解除する | OFF |
| GPU 温度しきい値 | 警告・危険の温度（設定ファイルで変更） | 80℃ / 90℃ |

- 設定変更は右クリックのコンテキストメニューから行う
- 不正な保存位置（モニター構成が変わり画面外になる等）の場合は主モニター中央に配置

### 4.4 更新

| 項目 | 内容 | 既定値 |
|---|---|---|
| 更新間隔 | 0.5 / 1 / 2 / 5 秒から選択 | 1 秒 |
| 履歴長 | グラフに表示する期間 | 60 秒 |

## 5. 非機能要件

| 項目 | 目標 |
|---|---|
| CPU 負荷 | 更新間隔 1 秒時、平均 1% 未満（一般的な 8 コア以上の CPU で）。実測: 0.06%（Ryzen 7 5700X、リリースビルド） |
| メモリ使用量 | 150MB 未満。実測: 約 110MB（うち OpenGL ドライバが約 60MB、日本語フォントが約 17MB） |
| 起動時間 | 1 秒以内に最初の画面を表示 |
| 精度 | タスクマネージャーの表示値と概ね一致（同時刻比較で ±数%） |
| 堅牢性 | デバイスの追加・削除（USB ディスク、VPN 接続等）でクラッシュしない。取得失敗した項目は「取得不可」と表示し、他項目の表示は継続 |

## 6. 技術仕様

### 6.1 使用技術

| 用途 | 採用 | 理由 |
|---|---|---|
| 言語 | Rust (stable, edition 2024) | 要件 |
| GUI | `eframe` / `egui` | 軽量・単一 exe・常に最前面/枠なし/透明度をサポート。即時モード GUI でグラフ描画が容易 |
| グラフ描画 | egui の `Painter` で自前描画 | 依存を減らし軽量化。必要なら `egui_plot` に置換 |
| OS API | `windows` クレート (windows-rs) | PDH / DXGI / IP Helper などを直接呼ぶ |
| 設定保存 | `serde` + `toml` | 人が読める設定ファイル |
| ログ | `log` + `env_logger`（デバッグ用） | ― |

### 6.2 データ取得方法

タスクマネージャーと値を揃えるため、主に **PDH（Performance Data Helper）カウンタ** を使用する。

| 項目 | 取得元 |
|---|---|
| CPU 使用率 | PDH `\Processor Information(_Total)\% Processor Utility`（タスクマネージャーと同じ指標）。論理コア別は `\Processor Information(*)\% Processor Utility` |
| CPU クロック | PDH `\Processor Information(_Total)\% Processor Performance` × 基本クロック（`\Processor Information(_Total)\Processor Frequency`） |
| メモリ | `GlobalMemoryStatusEx`（使用量・搭載量）、`GetPerformanceInfo`（コミット） |
| ページング | PDH `\Paging File(_Total)\% Usage`（使用率）、`\Memory\Pages Input/sec` / `Pages Output/sec`（× ページサイズでバイト/秒に換算）。ページファイルのサイズは `GetPerformanceInfo` の コミット上限 − 物理メモリ量 |
| ディスク | PDH `\PhysicalDisk(*)\% Idle Time`（100 − 値 = アクティブ時間）、`Disk Read Bytes/sec`、`Disk Write Bytes/sec`。インスタンス名 `0 C: D:` からディスク番号・ドライブレターを取得 |
| ネットワーク | `GetIfTable2` で各インターフェースの `InOctets` / `OutOctets` を取得し差分からスループット算出。`OperStatus`・`Type`・FilterInterface フラグでフィルタし、さらにレジストリ（ネットワークアダプタのデバイスクラス）の `Characteristics` に NCF_HIDDEN を持つアダプタを除外 |
| GPU 使用率 | PDH `\GPU Engine(*)\Utilization Percentage`。インスタンス名 `pid_XXXX_luid_0x..._0x..._phys_0_eng_N_engtype_3D` を解析し、LUID × エンジン種別ごとに合算 |
| GPU メモリ | PDH `\GPU Adapter Memory(*)\Dedicated Usage` / `Shared Usage` |
| GPU 名・総メモリ | DXGI `IDXGIFactory1::EnumAdapters1` → `DXGI_ADAPTER_DESC1`（`AdapterLuid` で PDH のインスタンスと突き合わせ） |
| GPU 温度 | `D3DKMTOpenAdapterFromLuid` で開いたアダプタに `D3DKMTQueryAdapterInfo(KMTQAITYPE_ADAPTERPERFDATA)` を発行し、`Temperature`（0.1℃ 単位）を取得。タスクマネージャーと同じ方法でベンダーを問わず、管理者権限も不要 |
| GPU ファン | 同じ `KMTQAITYPE_ADAPTERPERFDATA` の `FanRPM`。最大回転数は `KMTQAITYPE_ADAPTERPERFDATA_CAPS` の `MaxFanRPM` |

- PDH のワイルドカードカウンタは収集のたびにインスタンスが再列挙されるため、デバイスの増減に自動で追従する
- GPU Engine のインスタンスはプロセスの起動終了で頻繁に増減するため、`PdhGetFormattedCounterArray` で毎回全インスタンスを取得して集計する

### 6.3 アーキテクチャ

```
┌─────────────────────┐   スナップショット   ┌──────────────────┐
│ Collector スレッド   │ ───────────────────▶ │ UI スレッド       │
│ (更新間隔ごとに取得)  │  Arc<Mutex<History>> │ (eframe/egui)     │
│  - CpuCollector      │                      │  - タイル描画      │
│  - MemoryCollector   │                      │  - 設定メニュー    │
│  - DiskCollector     │                      │                    │
│  - NetworkCollector  │                      │                    │
│  - GpuCollector      │                      │                    │
└─────────────────────┘                      └──────────────────┘
```

- 取得処理は UI スレッドと分離し、取得の遅延で UI が固まらないようにする
- 履歴はリングバッファ（`VecDeque`）で保持
- 取得後に `egui::Context::request_repaint()` を呼び、データ更新時のみ再描画（アイドル時の無駄な描画を避ける）

### 6.4 モジュール構成

```
src/
├── main.rs            エントリポイント、ウィンドウ生成
├── app.rs             eframe::App 実装、レイアウト
├── config.rs          設定の読み書き
├── history.rs         リングバッファ・時系列データ
├── collector/
│   ├── mod.rs         スナップショット定義、収集スレッド
│   ├── pdh.rs         PDH の薄いラッパー
│   ├── registry.rs    レジストリ読み取り
│   ├── cpu.rs
│   ├── memory.rs
│   ├── disk.rs
│   ├── network.rs
│   └── gpu.rs
├── winutil.rs         ウィンドウ位置の保存・復元（Win32）
└── ui/
    ├── mod.rs         履歴から列・タイルを組み立てる
    ├── tile.rs        タイル共通描画
    ├── graph.rs       折れ線グラフ・小グラフ・メーター描画
    └── format.rs      単位変換（B/s, bps, GB など）
```

### 6.5 設定ファイル

保存先: `%APPDATA%\performance-monitor\config.toml`

```toml
update_interval_ms = 1000
history_seconds = 60
always_on_top = true
borderless = false
opacity = 1.0
compact = false
show_per_core_cpu = true   # CPU のスレッド別表示
gpu_temp_warning = 80.0    # GPU 温度の警告しきい値 (℃)
gpu_temp_danger = 90.0     # GPU 温度の危険しきい値 (℃)

# 非表示にしたタイルの ID
hidden = ["disk:2", "net:XXXXXXXX-XXXX-XXXX-XXXX-XXXXXXXXXXXX", "gpu:00000000_0001306e"]

# 前回終了時のウィンドウ位置・サイズ（物理ピクセル）
[window]
x = 100
y = 100
width = 1100
height = 640
```

## 7. 開発の進め方

### 7.1 マイルストーン

| # | 内容 | 完了条件 |
|---|---|---|
| M1 | プロジェクト雛形 | `cargo run` で空ウィンドウが常に最前面で表示される |
| M2 | CPU・メモリ | CPU・メモリのタイルがグラフ付きで表示される |
| M3 | ディスク | 全物理ディスクのタイルが表示される |
| M4 | ネットワーク | 接続中アダプタのタイルが表示される |
| M5 | GPU | 全 GPU のタイルがエンジン別グラフ付きで表示される |
| M6 | ウィンドウ設定 | 最前面/枠なし/不透明度/コンパクト/項目 ON/OFF、設定の保存・復元 |
| M7 | 仕上げ | 負荷計測・タスクマネージャーとの値比較、リリースビルド、アイコン設定 |
| M8 | 列レイアウト・温度 | 種類ごとの列レイアウト、CPU スレッド別表示、GPU 温度メーター |

### 7.2 バージョン管理（git）

- ブランチ: `main` を安定版とし、マイルストーン単位で `feature/<内容>` ブランチを切って作業、完了後に `main` へマージ
- コミットメッセージ: Conventional Commits 形式（`feat:`, `fix:`, `docs:`, `refactor:`, `chore:` など）
- `target/` などのビルド成果物は `.gitignore` で除外
- 仕様変更時は本書を更新し、`docs:` コミットとして記録

### 7.3 テスト方針

- 単位変換・インスタンス名解析（PDH の GPU/ディスク インスタンス名）・リングバッファはユニットテストを書く
- OS API に依存する取得処理は、実機でタスクマネージャーと並べて目視比較する
